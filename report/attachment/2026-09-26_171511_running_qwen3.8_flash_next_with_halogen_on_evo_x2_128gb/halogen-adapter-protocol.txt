====================================

Purpose
-------

  GMKtec EVO-X2 128GB / Radeon 8060S

- A custom Halogen API adapter called /v1/completions and recorded Halogen's

- Prompt cache: enabled

- Ladder generation length: 1000 tokens per stage

Why the prompt construction differs from stock llama-split-bench
----------------------------------------------------------------
Stock llama-split-bench grows its synthetic prompt with a moving TAIL.
With Halogen, a preflight showed that the common prefix was recognized
(prefix_n reported the shared prefix), but cache_n remained 0 for the
extension. In other words, the engine did not resume KV from that
intermediate shared-prefix point.

Therefore the final adapter uses literal prefix extension:
the entire previous-stage prompt becomes the literal prefix of the next
stage prompt.

Cache reuse evidence in the final run:
  32k   : cache_n =      0, prompt_n = 32021
  64k   : cache_n =  32021, prompt_n = 32004
  128k  : cache_n =  64025, prompt_n = 63980
  196k  : cache_n = 128005, prompt_n = 68005
  258k  : cache_n = 196010, prompt_n = 62020

For 64k and later, cache_n exactly matches the previous stage depth.
All final ladder stages reported disk_restore_n = 0.

Prefill semantics
-----------------
Halogen timings.prompt_n is the number of newly processed prompt tokens.
timings.prompt_ms is the engine time spent processing those tokens.
The reported prompt_per_second was independently checked as:

  prompt_n / (prompt_ms / 1000)

and matched to numerical precision.

Therefore the plotted ladder prefill values represent incremental prefill
of newly processed tokens, not full-context 0..N cold prefill.

Depth-0 PP0
-----------
Fresh-prompt measurements, cache_n = 0:
  529 tokens  ->  417.555 tok/s
  2048 tokens ->  852.729 tok/s
  8198 tokens -> 1175.694 tok/s

The plot uses the 2048-token PP0 value for depth-0 prefill, matching the
llama-split-bench plotter behavior.

Decode / real-prompt correction
-------------------------------
Synthetic ladder decode:
  stage 0 : 73.591 tok/s
  32k     : 74.028 tok/s
  64k     : 75.668 tok/s
  128k    : 74.678 tok/s
  196k    : 73.762 tok/s
  258k    : 72.335 tok/s

Real-prompt decode:
  design : 45.475 tok/s
  review : 39.227 tok/s
  qa     : 41.572 tok/s
  mean   : 42.091 tok/s

Correction factor:
  mean(real_decode / stage0_synthetic_decode)
  = 0.5719630570767259

The plotter applies this factor uniformly to the synthetic decode curve,
producing the thin dashed real-operation estimate.

Important interpretation:
- solid decode = measured synthetic-sequence decode
- thin dashed decode = real-prompt-corrected estimate
- the solid synthetic curve is MTP-friendly and should not be read as a
  typical real-prompt decode rate

MTP counters
------------
Raw Halogen draft counters were preserved in the JSON, but no acceptance
rate is published. Their semantics were not independently confirmed to be
identical to llama-split-bench/llama.cpp, and some stages report accepted
counts greater than draft_n.
